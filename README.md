## 📝 Comments for Revision

One important part of this repository is the use of **comments directly inside the code**.

Whenever a concept has an important rule, common confusion, edge case, or interview-relevant point, I may add a short comment for future revision.

For example:

```java
// Interface is not a class.
// A class can implement multiple interfaces,
// allowing multiple inheritance of type.
```

These comments serve three purposes:

### 🔄 Quick Revision

Instead of going through an entire topic again, I can open the code and quickly recall the important concept.

### 🧠 Understanding

Comments explain **why something works**, not just what the code is doing.

### 👥 Helping Others

Someone exploring the repository can understand the important concepts without having to figure everything out from the code alone.

The goal is to keep the comments **short, useful, and directly connected to the code**.

## 💻 Learning Through Implementation

This repository follows a simple approach:

```text
Learn the concept
       ↓
Understand the theory
       ↓
Write the code
       ↓
Experiment & break it
       ↓
Fix the mistakes
       ↓
Add useful revision comments
       ↓
Revisit later
```

Writing the code is only part of the process. The main goal is to understand **why the code behaves the way it does**.
